# Repository Agent Policy

## Documentation Definition of Done

Documentation is part of every task's Definition of Done, whether or not code changes are required.

Before completing any task:

1. Review `APP_RECAP.md`, `PROJECT_STATE.json`, and `SaaS_Aviation/CTO_STATUS.md`; update them whenever the task changes or clarifies repository state.
2. Review and update every affected document under `docs/`, including architecture, business, database, deployment, testing, security, API, migration, and roadmap documentation as applicable.
3. Record module progress, completed and missing work, known blockers, the next recommended task, validation actually performed, deployment status, and the relevant commit when available.
4. State only verified facts. Never describe an unexecuted, skipped, blocked, or failed check as passing.
5. Keep deployment truth explicit, including whether the public frontend, API, database, Yoyamic, or legacy PHP changed.

A task is incomplete until its code and documentation describe the same verified repository state.
